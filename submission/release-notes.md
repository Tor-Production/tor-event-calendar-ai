# 0.2.0 candidate release notes

This candidate introduces the Nembli name and `https://nembli.com` origin, with the remote MCP endpoint at `https://nembli.com/mcp`, installation guide at `/connect-ai`, and privacy policy at `/privacy`. The plugin combines the explicitly invoked `tor-event-calendar` skill with account-scoped remote tools and browser OAuth. Its package ID `tor-event-calendar-ai`, CLI command `tor-calendar`, skill ID and repository remain stable. The calendar icon now carries an N.

The skill checks the selected account, exact date/time and IANA timezone, asks only for missing platform-specific values, and preserves arbitrary `customFields`, explicit `customFieldTypes` and File metadata. File bytes use browser-owned links. Calendar writes never publish or schedule social content; `publication_automated` still requires confirmed end-to-end publishing setup.

New 0.2.0 CLI connections default to Nembli. Existing profiles, their saved origins and the OS keyring service are preserved. An OAuth grant for a previous origin cannot authorize Nembli, and redirects do not transfer access. Reconfigure the client and approve a fresh browser grant, verify the account, then deliberately revoke an old connection if desired. The published v0.1.0 CLI keeps its original default but supports an explicit `--origin https://nembli.com`. [Migration instructions](../skills/tor-event-calendar/references/connections.md#moving-an-existing-connection-to-nembli)

Version 0.2.0 remains a candidate associated with [draft PR #1](https://github.com/Tor-Production/tor-event-calendar-ai/pull/1) to `develop`. The published v0.1.0 release is unchanged. The existing OpenAI With MCP draft must be updated and rescanned for Nembli; earlier skill scans, old-domain verification, SDK reads and private ChatGPT refresh checks do not verify the new package or origin. Native installed-plugin OAuth, reviewer demo/scenarios, policy review, submission, approval and public listing remain separate gates. [Status and evidence](status.md)
