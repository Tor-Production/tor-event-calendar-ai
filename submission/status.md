The [OpenAI submission guide](https://developers.openai.com/plugins/deploy/submission) distinguishes the public **With MCP** flow from local packaging: the publisher submits the HTTPS server URL directly and uploads or imports the skill. The full portable ZIP is useful for local/plugin distribution but its `.app.json` reference, if any, cannot replace the server submission. A Skills-only upload would exclude MCP configuration. Submission starts review, and only subsequent approval plus developer publication makes a public directory listing available. [Submission errors](https://developers.openai.com/plugins/deploy/submission-errors) · [public publishing flow](https://developers.openai.com/plugins/deploy/app-review)

The updated [installation-page source](../docs/index.html) keeps the intended one-plugin route first and labels its current pending state; those changes are not live on GitHub Pages until published. Manual Streamable HTTP MCP setup is an optional tool-only fallback; it does not install the skill. The [calendar-site handoff](calendar-site-handoff.md) gives the exact configuration keys, endpoint, consent boundaries and publication gate.
