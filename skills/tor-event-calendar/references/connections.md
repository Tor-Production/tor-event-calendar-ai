# Connections

The CLI runs locally with Node 22.18+ and stores tokens in Windows Credential Manager, macOS Keychain or Linux Secret Service via pinned `@napi-rs/keyring` 2.1.0. Linux explicitly requires Secret Service; a missing/locked store fails closed. Only non-secret profile metadata is written to `%LOCALAPPDATA%/tor-event-calendar/profiles.json` (Windows) or `~/.config/tor-event-calendar/profiles.json` (macOS/Linux), outside repositories and installed skills.

`connect [--scope read|manage] [--name DEVICE] [--no-browser] [--default]` starts a device authorization pattern with a 10-minute single-use code, 5-second minimum polling and an S256 verifier binding. Check the browser's verified email, immutable calendar account ID, requesting device, code and requested permission. The token appears only in the HTTPS exchange and OS keychain; it is never printed or placed in argv, URLs, prompts or browser storage. Consent connects this local runtime only. `read` cannot mutate; `manage` covers calendar CRUD, files, preferences, receipt reporting and publication claims, not social network authorization. Paired tokens expire after 90 days and can be revoked independently.

`accounts list`, `accounts default VERIFIED_EMAIL_OR_ID`, `whoami --account SELECTOR`, `status`, and `disconnect --account SELECTOR` manage multiple connections. A single profile can be used without another approval. Multiple profiles need an explicit selector or explicitly selected default; every batch pins an immutable origin/account. Email is server-verified human metadata, not ownership. Changes to email refresh the same ID's metadata. Invalid/revoked credentials and mismatches never fall through to another profile or cookie. Reconnect only updates that profile; previous tokens remain visible for revocation in browser settings. Existing unrelated helper/automation tokens are preserved.

`disconnect` revokes this connection then removes the local credential/profile. `--local-only` forgets it locally, for example after independent browser revocation; it does not claim server revocation. Upgrading or uninstalling the CLI/skill leaves profiles and keychain intact. The skill installer replaces only its marked installations; it refuses an existing junction or unowned skill. Preserve an owner's junction and update its source deliberately.

All local agent ecosystems under the same OS user can reuse one CLI connection. Each other machine/cloud/container needs its own connection or secret-manager injection. ChatGPT cloud cannot access the local keychain. No MCP/cloud OAuth connector is implemented in v0.1.0.

Headless route: use your runtime's secret manager to inject `TOR_EVENT_CALENDAR_API_TOKEN`, then explicitly pass `--environment --account IMMUTABLE_SERVER_ACCOUNT_ID [--origin HTTPS_ORIGIN]`. The CLI verifies `/api/me` before private work. Never type the secret as a command, commit it, or copy it into the chat. This is an explicit environment route, not an automatic fallback. There is no plaintext-file fallback, so Unix chmod is never treated as Windows ACL protection. An owner managing secret files independently must restrict real Windows ACLs or POSIX owner permissions before injection; that file workflow is outside this client.

`doctor` probes a random synthetic keychain entry, deletes it, retrieves public capability limits and lists non-secret profile identity metadata. It makes no private calendar writes or social calls. `whoami` confirms the selected account read-only. Pairing response loss after consumption requires fresh consent; no debug token retrieval exists.
