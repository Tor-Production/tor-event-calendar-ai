Codex and ChatGPT

Install one plugin

The public directory entry is not available yet. The plugin is a saved submission draft; the current CLI release is a separate option below.

Open Nembli in Plugins Directory (opens in a new tab) Directory install pending
  1. When the public listing appears here, open it while signed in to the ChatGPT account you use with Codex. In the desktop app, open Plugins, find Nembli by Tor Production, and select + to install.
  2. The plugin supplies both the tor-event-calendar skill and the remote calendar MCP connection. Open a new Codex task so the installed components are available; select the plugin in the task if your client asks.
  3. When Codex asks to connect, continue to browser sign-in. Check the calendar account shown there and approve only the permissions you intend to use. Choose the correct verified email or account ID if you use more than one account.
  4. Try a bounded read: “Use $tor-event-calendar to show my connected account and the next five calendar entries. Do not change anything.”

The browser authorization starts from the AI client. Opening the calendar site by itself does not connect the plugin. Switching accounts on the website also does not transfer an existing plugin grant to another account.

What the connection does

Skill + tools

The skill guides calendar workflows. The hosted MCP server supplies account-scoped tools for profile, capabilities, entries, drafts and supported file links. Both belong to the same plugin install.

Browser consent

The calendar asks you to sign in and authorize calendar.read for reads and calendar.manage for changes. offline_access may be requested for a connection that can refresh. Never paste an API token into a chat.

Your account and time

Check the selected account and exact time zone before changes. The plugin can prepare or manage a calendar entry, but a calendar write does not publish or schedule a social post.

File links are handled by the browser; file bytes are not put in MCP JSON. The calendar's file limit is 25 MiB. Revoke a connection from calendar account settings when you no longer want that client to use it.

Optional fallback

Add the remote MCP manually

If your client can connect to an OAuth-protected Streamable HTTP MCP server, add this HTTPS endpoint in that client's MCP settings. This connects the tools; it does not install the calendar skill. The directory plugin above is the intended combined install.

Loading endpoint…

Let your client start OAuth discovery and browser sign-in. Use the exact account and scopes you choose there; do not add a token or local proxy. If this page cannot load its configuration, see the source repository for the current endpoint.

Moving an existing connection to Nembli?

Use https://nembli.com/mcp for a new connection. Grants for eventcalendar.torproduction.com or the former workers.dev origin remain tied to their original origin. Update the connection URL in your AI client, complete a fresh browser sign-in and consent, then confirm your account and a small calendar read before revoking the old connection.

Existing CLI profiles keep their saved origins and credentials. To pair with Nembli explicitly, run tor-calendar connect --origin https://nembli.com --default, then verify with tor-calendar whoami. Use the exact old profile ID if you later disconnect it. The connection guide explains account and origin selection.

Install the current local CLI (0.2.0)

The 0.2.0 release includes a local CLI, standalone skill and combined plugin ZIP. The CLI requires Node 22.18+ and an unlocked OS keychain. Its account pairing is separate from MCP OAuth.

npm install -g https://github.com/Tor-Production/tor-event-calendar-ai/releases/download/v0.2.0/tor-event-calendar-ai-0.2.0.tgz
tor-calendar install-skill codex
tor-calendar connect --origin https://nembli.com --default
tor-calendar whoami

The CLI defaults new connections to Nembli. Existing profiles keep their saved origin until you deliberately pair a new connection.

Already using the v0.1.0 local CLI?

The v0.1.0 release remains an optional local route using Node.js and the OS keychain. Its standalone skill and connection are separate from the new remote plugin. Keep your existing connection until you deliberately revoke it; an OAuth grant for one server origin or account does not move automatically to another.
