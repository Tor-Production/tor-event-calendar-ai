Privacy · nambli

The current service policy is at nambli.com/privacy. This page describes the AI integration.

The nambli integration connects an AI client to the calendar's hosted MCP service. The installation guide shows current directory availability and the optional manual route.

Connecting an account

When you connect from a supported client, that client opens the calendar's browser sign-in, where you approve an account-bound OAuth grant. The available scopes are calendar.read, calendar.manage and optional offline_access for refresh. The calendar checks the account, grant, scopes, audience and token expiry on MCP requests. Browser session cookies and legacy calendar API tokens do not authorize MCP access.

The AI client manages its own connection credentials according to that client's policy. The public plugin package contains no customer token or credential, and you should never paste a token into a prompt. The optional local CLI is a separate route: it stores its token in the OS credential store and non-secret account metadata in user-scoped configuration.

Calendar data

The calendar service stores verified account identity, your entries and attachment metadata in its database. File bytes are stored privately in Cloudflare KV. When you ask the plugin to attach a chat file, the AI host supplies a temporary download link and the calendar downloads that file into private storage. Website uploads and downloads use authenticated requests. File bytes, local paths and temporary download links are not saved in event JSON; the MCP result returns attachment metadata. The AI host also handles the file under its own privacy settings. Calendar data you request through an AI client is returned to that client, whose own privacy terms and settings also apply. Calendar writes do not publish or schedule social content.

Access is tied to the chosen calendar account and exact service origin. Switching accounts on the website does not transfer a grant. You can revoke a client connection in calendar account settings; the service checks revocation on subsequent MCP requests. Removing a local skill or CLI does not itself revoke a separate grant.

Questions and requests

For privacy requests, use project support. Do not include private events, tokens or files in public issues.
